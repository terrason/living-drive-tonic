# ldt-trace

## Overview

`trace` 是一个系统观测子命令，用于持续分析本地系统的写入行为，并将这些行为按用户定义的目录分类进行聚合统计。

它帮助用户回答一个核心问题：

> “我的系统中，哪些目录正在被最频繁地写入？”

---

## What it does

`trace` 会在后台持续观察系统文件活动，并将每一次文件写入事件归类到用户配置的“汇总目录”中。

对于每个匹配到的目录，它会累加写入次数，并形成一个长期统计结果。

最终用户可以获得：

- 哪些目录最活跃
- 文件系统写入行为的热点分布
- 长期运行的写入活动趋势

---

## Key capabilities

### 1. 文件写入监控

trace 持续监听文件系统写入事件，这些事件来源于底层系统的实时文件系统活动。

---

### 2. 目录级别聚合统计

用户可以预先配置一组“汇总目录”。汇总目录以`/`结尾表示其下级才是真正的汇总目录。

trace 会将所有文件路径映射到这些目录，并进行统计：

- 命中某个目录 → 该目录计数 +1
- 未命中目录 → 忽略（或记录为未分类事件）

---

### 3. 访问频率分析

trace 不关注单个文件的细节，而关注：

- 哪些目录最频繁被写
- 哪些区域产生最多文件系统活动
- 系统行为的“热点区域”

---

### 4. 长期运行统计

trace 设计为长期运行工具：

- 可持续运行数小时至数天
- 自动累积统计数据
- 提供稳定的趋势观察能力

---

### 5. 周期性结果保存

统计结果会定期保存到本地数据库中，使得：

- 数据不会随进程结束丢失
- 可以跨会话持续累积分析结果
- 支持后续查询与排序

---

## Output

trace 本身不会生成复杂报表，而是维护一组持续更新的统计数据，例如：

- 每个汇总目录的写入次数
- 当前累计统计状态

这些数据可由其他 ldt-config 子命令读取和展示。

---

## Typical use cases

- 分析系统哪些目录最频繁被写入
- 识别高 IO 活动区域（例如 cache、build、browser data）
- 优化磁盘布局或目录挂载策略
- 理解应用程序的文件写入模式
- 长期监控开发环境行为变化

---

## Design philosophy

trace 的设计遵循以下原则：

- **简单优先**：只做目录级统计
- **长期运行**：适合后台持续运行
- **低侵入性**：不影响系统正常使用
- **非精确导向**：关注趋势，而不是精确审计
- **本地工具**：面向单机用户环境

---

## Limitations

trace intentionally does NOT provide:

- 精确 IO profiling
- 每个文件的完整历史记录
- 实时告警系统
- 分布式分析能力
- 高级查询语言

它的目标是“理解系统热点”，而不是“完整记录系统行为”。
